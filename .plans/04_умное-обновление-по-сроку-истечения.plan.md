# План: Умное обновление сертификатов по сроку истечения

## Статус: ГОТОВО

## Цель
Изменить логику с «обновлять все при каждом запуске» на «запускать ежедневно, обновлять только те сертификаты, у которых истекает срок».

## Контекст
Текущая программа — one-shot: запускается (обычно по cron) и безусловно перевыпускает **все** сертификаты через ACME DNS-01. Нет проверки срока действия. Нужно добавить умную логику:
- ежедневный запуск по cron
- перевыпуск только если сертификат истекает в ближайшие N дней
- сохранить ручной принудительный выпуск через флаг `--force`

## Критерий готовности
- `go build ./...` успешен
- При запуске с актуальными сертификатами (> 30 дней) — программа их пропускает и отправляет уведомление с днями до истечения
- При запуске с `--force` — перевыпускает все сертификаты как раньше
- `--certs name --force` — принудительный ручной выпуск конкретного сертификата

## Поведение флагов

| Комбинация | Поведение |
|---|---|
| *(без флагов)* | Проверить все сертификаты, обновить только истекающие |
| `--force` | Обновить **все** сертификаты, игнорируя срок |
| `--certs name1,name2` | Проверить только эти сертификаты, обновить только истекающие среди них |
| `--certs name1,name2 --force` | Принудительно обновить только эти сертификаты (ручной выпуск) |
| `--list` | Показать имена всех сертификатов и выйти (без изменений) |
| `--debug` | Подробное логирование (без изменений) |
| `--config path` | Путь к конфигу (без изменений) |

`--force` и `--certs` независимы и комбинируются естественно: `--force` управляет тем, игнорировать ли проверку срока; `--certs` — каким набором сертификатов заниматься.

Для ежедневного cron: `./letsencrypt-certificate --config config.ini`
Для ручного перевыпуска: `./letsencrypt-certificate --config config.ini --certs example.com --force`
