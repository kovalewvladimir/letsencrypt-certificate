# letsencrypt-certificate

Утилита для автоматического получения и деплоя Let's Encrypt SSL-сертификатов через DNS-01 challenge (NIC.RU).

> Проект переписан с Python на Go с помощью ИИ — модели **Claude Sonnet 4.6** (`claude-sonnet-4-6`, Anthropic).
> Причина: устаревшие Python-зависимости (заморожены на версиях 2018–2019 годов) и необходимость деплоить утилиту как единый статичный бинарник без установки окружения на целевых серверах.

## Что делает

1. Получает сертификаты от Let's Encrypt по протоколу ACME (DNS-01)
2. Создаёт TXT-записи в NIC.RU DNS для подтверждения домена
3. Деплоит сертификаты на серверы — локально или по SSH
4. Проверяет SSL на всех портах и отправляет отчёт в Telegram / Max.ru

## Конфигурация

```bash
cp config.ini.example config.ini
# заполнить config.ini
```

Ключевые секции `config.ini`:

| Секция | Что настраивает |
|---|---|
| `[log]` | Путь к лог-файлу (`folder`), папка сертификатов (`certificate_folder`) |
| `[log.http]` | Отправка логов по HTTP на удалённый сервер (опционально) |
| `[notifier.telegram]` | Уведомления через Telegram — токен бота и `recipient` |
| `[notifier.maxru]` | Уведомления через Max.ru — `access_token` и `chat_id` |
| `[acme]` | URL Let's Encrypt (`directory_url`), email |
| `[nic]` | Учётные данные NIC.RU API, `token_file` для кэша токена |
| `[dns]` | Интервал и лимит проверки TXT-записи, DNS-резолвер |
| `[certificate "name"]` | Домены, порты, тип деплоя (`local`/`ssh`), `renew_before_days` |

Можно подключить одновременно несколько нотификаторов — каждый из блоков `[notifier.*]` будет использован независимо.

Для тестов используйте staging в `[acme]`:
```ini
directory_url = https://acme-staging-v02.api.letsencrypt.org/directory
```

### HTTP-лог (опционально)

Блок `[log.http]` позволяет дублировать каждую строку лога на удалённый HTTP-сервер POST-запросом:

```ini
[log.http]
enable      = true
host        = 192.168.1.100
port        = 8080
read_port   = 8080   ; порт для ссылки в уведомлении
path        = letsencrypt-certificate
timeout_sec = 10
```

URL записи: `http://host:port/path/<logFileName>`, тело: `t=<строка>&no_date=true`.
Если `read_port` не задан, ссылка на лог в уведомлении не выводится.

## Логика обновления

Программа запускается ежедневно (по cron) и проверяет срок действия каждого сертификата.
Обновление выполняется только если до истечения осталось не более `renew_before_days` дней (по умолчанию 30).
Если все сертификаты актуальны — уведомление отправляется без обращения к NIC.RU и Let's Encrypt.

## Флаги

| Флаг | Описание |
|---|---|
| `--config path` | Путь к файлу конфигурации (по умолчанию `config.ini`) |
| `--debug` | Включить подробное логирование |
| `--list` | Показать имена всех сертификатов и выйти |
| `--certs name1,name2` | Обработать только указанные сертификаты |
| `--force` | Принудительно обновить, игнорируя срок истечения |

Комбинации:
- Ежедневный cron — без флагов: `./letsencrypt-certificate --config config.ini`
- Ручной перевыпуск конкретного сертификата: `./letsencrypt-certificate --config config.ini --certs example.com --force`
- Принудительное обновление всех: `./letsencrypt-certificate --config config.ini --force`

## Сборка и запуск

```bash
make build   # статичная сборка бинарника (CGO_ENABLED=0)
make run     # запуск с config.ini
make vet     # проверка go vet
make clean   # удалить бинарник
```

Или напрямую:
```bash
./letsencrypt-certificate --config config.ini
```

## Зависимости

Единственная внешняя зависимость: `golang.org/x/crypto` (ACME + SSH).
Всё остальное — стандартная библиотека Go.

---

## Анализ: Python vs Go

### Объём кода

| Версия | Файлов | Строк кода | Внешних зависимостей |
|--------|--------|-----------|----------------------|
| Python (master) | 11 | ~1 331 | 7 |
| Go (AI-go) | 14 | ~1 856 | 1 |

Go версия на ~40% длиннее — это ожидаемо: явная обработка ошибок (`if err != nil`), строгая типизация и отсутствие "батареек" для некоторых задач (парсинг INI, SOCKS5) требуют больше кода.

### Зависимости

Python-версия тянула 7 сторонних пакетов, часть из которых сильно устарела на момент переписывания (`acme==0.34.2` — 2018 год, `dnspython==1.16.0` — 2019 год). Обновление зависимостей рискует сломать API. Уязвимости в одной из библиотек автоматически становятся уязвимостью проекта.

Go-версия использует одну зависимость — `golang.org/x/crypto`, которая является официальным расширением стандартной библиотеки и поддерживается командой Go. Всё остальное (HTTP, DNS, SSH, TLS, INI) реализовано через stdlib.

### Деплой

| Аспект | Python | Go |
|--------|--------|----|
| Среда выполнения | Python 3 + virtualenv + pip install | Ничего — один статичный бинарник |
| Деплой на сервер | Копировать код + установить зависимости | Скопировать один файл |
| Зависимость от ОС | Нет (нужен только Python) | Нет (статичная сборка `CGO_ENABLED=0`) |

### Поддержка

**Python проще читать** в небольших скриптах — меньше синтаксического шума. Однако для этого проекта это преимущество не решающее: логика достаточно сложная (ACME, OAuth, SSH, DNS polling), и в Python ошибки типов и пустые возвраты обнаруживались только в рантайме.

**Go проще поддерживать** на горизонте 2–3 лет:
- Компилятор ловит целый класс ошибок до запуска
- Все зависимости стабильны и не требуют регулярного `pip install --upgrade`
- Горутины позволили проверять несколько сертификатов параллельно без `Thread`/`concurrent.futures`
- Бинарник деплоится без установки окружения на целевой сервер

### Вывод

Переписывание на Go было оправдано. Главные выигрыши — **не скорость и не размер кода**, а:

1. **Устранение устаревших зависимостей** — Python-версия была заморожена на пакетах 2018–2019 годов и фактически не могла безопасно обновляться.
2. **Единый статичный бинарник** — для cron-утилиты, деплоящейся на серверы, это существенное упрощение эксплуатации.
3. **Надёжность** — явная обработка ошибок и типизация делают поведение программы предсказуемым; код стал длиннее, но менее хрупким.

Если бы зависимости Python активно поддерживались, а деплой происходил только в одну среду с уже установленным Python — переписывание было бы преждевременным. В данном случае оно устранило реальные операционные проблемы.
